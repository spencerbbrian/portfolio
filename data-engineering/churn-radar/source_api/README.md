# Churn Radar Source API

Stands in for a real SaaS product's API. On first startup it generates ~400 synthetic
customers (with realistic healthy/at-risk/churned behavior patterns -- see the main
project README) into a local SQLite file (`data.db`), then serves that data over HTTP
with cursor-based pagination, matching how a real incremental REST API source behaves.
This is what Airbyte will be configured to pull from in a later step.

## Running locally

```bash
cd data-engineering/churn-radar/source_api
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt

uvicorn main:app --reload
```

Then in another terminal:

```bash
curl http://127.0.0.1:8000/health
curl http://127.0.0.1:8000/customers | head -c 500
curl http://127.0.0.1:8000/events/usage | head -c 500
curl http://127.0.0.1:8000/events/billing | head -c 500

# incremental-style pagination -- only rows after a given cursor
curl "http://127.0.0.1:8000/customers?since=2025-01-01T00:00:00&limit=50"
```

Interactive API docs (auto-generated by FastAPI) are at `http://127.0.0.1:8000/docs`
once the server is running -- useful for browsing the endpoints without curl.

To wipe and regenerate the dataset without restarting the server:

```bash
curl -X POST http://127.0.0.1:8000/admin/regenerate
```

## Running via Docker

```bash
docker build -t churn-radar-source-api .
docker run -p 8000:8000 churn-radar-source-api
```

## What to sanity-check

- `/customers` returns ~400 rows, mostly `status: active`, some `status: canceled`.
- `/events/usage` returns thousands of rows across `login`, `feature_used`,
  `support_ticket_opened`, and `support_ticket_resolved` event types.
- `/events/billing` returns `subscription_started` for every customer, plus a mix of
  `plan_upgraded`, `payment_failed`, and `subscription_canceled` events.
- Cross-check a canceled customer's usage events -- their `event_timestamp` values
  should cluster well before their cancellation date, not right up to today, which is
  the "quiet before they leave" signal the health-score model will key off of later.
